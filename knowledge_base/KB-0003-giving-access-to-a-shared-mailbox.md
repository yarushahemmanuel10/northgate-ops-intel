# Giving access to a shared mailbox

> Synthetic document. Northgate IT Services Ltd is a fictional company; this text was written for a portfolio prototype.

## When to use this article

Use it when a manager asks for a member of staff to be given access to a shared mailbox, such as an accounts or enquiries mailbox, or when a user who should already have access cannot see the mailbox in Outlook.

## Check the request

Requests for access must come from the user's line manager or from the mailbox owner recorded by the customer. If the request comes from the user themselves, ask them to get their manager to confirm by replying on the ticket. Note on the ticket which permissions are needed:

- **Full access** lets the user open and read the mailbox.
- **Send as** lets the user send email that appears to come from the shared mailbox.
- **Send on behalf** shows both the user's name and the shared mailbox name on sent email.

## Granting access

1. Open the shared mailbox in the email admin centre.
2. Add the user under mailbox delegation with the permissions agreed on the ticket.
3. Where the customer uses security groups for shared mailboxes, add the user to the group instead of granting access directly. This keeps permissions tidy when staff leave.
4. Tell the user the mailbox will appear in their folder list automatically after Outlook has restarted. On some computers this takes longer than expected.

## When the mailbox does not appear

- Ask the user to close Outlook fully and open it again.
- Check that the permission was granted to the correct account, especially where two staff share a surname.
- If the mailbox appears in webmail but not in Outlook, remove any stale cached entry for the mailbox from the user's account settings and restart Outlook.
- If the user was recently given access through a group, the change may need to finish syncing before it shows.

## Removing access

When access is no longer needed, remove the user from the delegation list or the group, and record who asked for the removal.
